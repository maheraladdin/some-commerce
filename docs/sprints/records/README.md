# Canonical Sprint Records

> **Scope**: Sprint Operational Execution History · Agent Task Handoffs · Gate SG0–SG4 Tracking  
> **Template**: [`SPRINT_RECORD_TEMPLATE.md`](./SPRINT_RECORD_TEMPLATE.md)  
> **Accountable Roles**: `tech-lead` / `release-gatekeeper` / `chief-technology-officer`

This directory contains the **canonical operational records** for each sprint execution in `some-commerce`, named `SPRINT-<id>.md` (e.g. `SPRINT-1.1.md`), instantiated from [`SPRINT_RECORD_TEMPLATE.md`](./SPRINT_RECORD_TEMPLATE.md) when a sprint enters planning at SG0.

## Relationship to Other Documentation Hubs
- **Sprint Specifications & Plans**: [`docs/sprints/sprint-<id>.md`](../) defines the approved scope and agent workload allocations.
- **Sprint Execution Records** (*This Directory*): Tracks the living operational progress, PR merges, gate transitions, and handoffs.
- **Sprint Audits**: [`docs/audits/`](../../audits/) preserves formal security, zero-clone, and compliance reviews (SG2 / SG3).
- **Sprint Reports**: [`docs/reports/`](../../reports/) stores empirical test outputs, Criterion benchmarks, fuzzing, and closeout packages (E1–E5 / SG1 / SG4).
- **Sprint Retrospectives**: [`docs/sprints/retrospectives/`](../retrospectives/) stores post-sprint lessons learned and continuous improvement action items.
